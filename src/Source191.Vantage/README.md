# Source191.Vantage

The packed tool: `Program.cs` and its `Composition` folder, the only composition root, wire Core, Infrastructure and Tui together, and packing includes those three projects. `Program.cs` keeps the process-wide start (`SharedParts`, Terminal.Gui's logger, the crash hooks and the command line); `LaunchParts` is the console's and `vantage here`'s shared preamble, which checks `RequiredPrograms`, prints the sentence and exits 1 when Claude Code or git cannot be run; `ConsoleComposition`, `HereComposition` and `TerminalSetupComposition` construct one command each. Everything here is untested wiring, checked by the build, the hand-off check and CI's smoke check: each decision it once held is a tested class in Core's `Application` (`ConsoleLoads`, `Started.From`, `UpdateCheckSwitch`, `HeaderSettingsRow`, `RequiredPrograms`). Construction is by hand: a dependency injection container was weighed in the `tidy-composition-root` change and rejected, because many arguments are strings, delegates or several values of one type, start-up is async, and a missing registration would fail at run time rather than in the build. The user guide is the repository's [README](../../README.md), which is also the package readme on nuget.org; `THIRD-PARTY-NOTICES.txt` travels beside the tool and in the winget zip, as the licences of the packed dependencies ask. The project builds two things: the dotnet tool nupkg (`dotnet pack`), kept only for the release that moves nuget.org users to winget, and the self-contained winget build (`dotnet publish -p:PublishProfile=win-x64`).

## Package settings

- **`SatelliteResourceLanguages` `en`:** Vantage is English only, so the translated resources of System.CommandLine and Terminal.Gui are neither built nor packed, and those libraries' own messages stay English on every Windows display language.
- **`IncludeSourceRevisionInInformationalVersion` false:** `vantage --version` prints exactly the version that the GitHub Release and winget show, with no `+<commit>`. The commit is still recorded in the package's repository metadata. The `check` job asserts this on the unzipped winget build.
- **`PackageReleaseNotes`:** the whole of the root `CHANGELOG.md`, read at evaluation with `File.ReadAllText`, so nuget.org shows it (the update check now reads a newer release's notes from the changelog at its tag, `WingetPackageVersions.NotesAsync`). It goes with the nupkg. It is packed as written, Unreleased and Internal included: Vantage drops both when it reads the notes, so packing needs no script. nuget.org takes at most 35,000 characters, which `Assert-ChangelogUpdated.ps1` holds the file under.
- **`CHANGELOG.md` beside the tool:** copied to the output and so packed in `tools\net10.0\any`, as `vantage.ico` is, where `PackagedReleaseNotes` reads it on the first start of a new version without a network request.
- **The `RemoveNonWindowsNativeAssets` target:** Terminal.Gui depends, through TextMateSharp, on Onigwrap, whose `libonigwrap` ships for thirteen platforms; the target drops every published file whose runtime identifier is not a Windows one, so the package keeps only `win-x64`, `win-arm64` and `win-x86`, and the shared pack step fails if any other platform's assets come back. RID-specific tool packages were tried instead and rejected: they install a `vantage.cmd` shim and a versioned executable path that breaks `U` and the terminal profile after every update.
- **`ContinuousIntegrationBuild`:** set under GitHub Actions in the root `Directory.Build.props`, which explains it, so the packed assemblies are deterministic.
- **`InvariantGlobalization`:** the one project where the setting takes effect, because only an executable's `runtimeconfig.json` carries it; the libraries leave it off (their READMEs say why) and the test projects set it so they run as the tool does.
- **`vantage.ico`:** `assets\icon\vantage.ico` is copied beside `vantage.exe`, where `vantage setup-terminal` finds it and copies it next to the Windows Terminal fragment as the profiles' tab icon.

## The winget build

`Properties\PublishProfiles\win-x64.pubxml` holds the publish settings, so `dotnet pack` and `dotnet build` stay as they were (a self-contained or RID-specific setting in the project would make the nupkg a RID-specific tool, which the `RemoveNonWindowsNativeAssets` entry above explains was rejected). `dotnet publish src\Source191.Vantage -p:PublishProfile=win-x64` writes `artifacts\publish`, which the `build-test-pack` action zips.

- **`SelfContained` and `RuntimeIdentifier` `win-x64`:** the program carries its own .NET runtime, so a machine needs neither the SDK nor the runtime. `win-arm64` is left for a later change; x64 runs under emulation on Arm Windows.
- **`PublishSingleFile` and `EnableCompressionInSingleFile`:** one `vantage.exe` (about 40 MB, 34 MB zipped, measured 1 November 2026 on .NET 10.0.403) beside `libonigwrap.dll`, Terminal.Gui's native library, which stays a file of its own. A single-file bundle has no assembly file, which is how `InstallChannels` tells the winget build from the dotnet tool. Not trimmed and not native AOT: Terminal.Gui and System.CommandLine use reflection the trimmer would need annotating for.
- **`CopyOutputSymbolsToPublishDirectory`, `PublishDocumentationFiles`, `PublishReferencesDocumentationFiles` false and `AllowedReferenceRelatedFileExtensions` `.none`:** the PDBs and XML documentation files of the program and the three projects it references are left out, so the folder holds exactly what the zip ships: `vantage.exe`, `libonigwrap.dll`, `CHANGELOG.md`, `vantage.ico` and `THIRD-PARTY-NOTICES.txt` (copied by `CopyToPublishDirectory`).
- **`PublishDir`:** `artifacts\publish` at the repository root, beside `artifacts\packages`, both ignored by git.
