# Source191.Cader.NoisyEditor

A stand-in for an editor that prints as it starts, which `DesktopShould` starts through `Desktop.StartAsync` to check that nothing it writes reaches the console's own standard handles or its console (issue #210). Handed no standard output, it attaches to its parent's console as Electron, and so VS Code, does unless [`ELECTRON_NO_ATTACH_CONSOLE`](https://github.com/electron/electron/blob/main/docs/api/environment-variables.md) is set, writes a line to standard output and one to standard error, then writes the file named by its first argument with the ids of the processes on the console it attached to on its first line and each of its other arguments on a line of its own. No test framework here, and nothing in it is shipped.

- **`OutputType` `WinExe`:** editors are windowed programs, which Windows gives no console of their own. A console program would get a hidden console of its own under `CreateNoWindow` and keep its output to itself, so it could not show the fault this stands in for.
- **`AllowUnsafeBlocks`:** the `[LibraryImport]` source generator behind `GetStdHandle`, `AttachConsole` and `GetConsoleProcessList` refuses to run without it; the project writes no `unsafe` code of its own.
