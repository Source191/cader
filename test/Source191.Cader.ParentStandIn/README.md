# Source191.Cader.ParentStandIn

A stand-in for a process that starts a program and either waits or exits, which `ProcessApisShould` uses three ways: as Cader's captured child starting a sleeper that shares its redirected handles, as Cader itself, killed alone as a crash would end it, to see what `ProcessStartInfo.KillOnParentExit` (new in .NET 11, Windows only) ends with it, and as that parent's child starting a sleeper and exiting, as a daemon's starter does. Its arguments are how to start the program (`kill-on-parent-exit`, `plain` or `shell-execute`, the last hidden), what to do then (`wait` to be killed, or `exit`), the file to write the started program's id to, and the program with its arguments. No test framework here, and nothing in it is shipped.

- **Its own program:** `KillOnParentExit` is .NET 11's, so the parent must run on .NET 11; the test process cannot be killed to show it, and the runner image's PowerShell (7.6.9 on 3 November 2026) still runs on .NET 10. A .NET program also starts in a fraction of the time PowerShell takes, which keeps the run-and-capture facts' limits short, and on the owner's machine a start under `KillOnParentExit` was refused for a packaged program's app execution alias, such as the Microsoft Store PowerShell's `pwsh.exe`, so the child cannot be PowerShell there.
